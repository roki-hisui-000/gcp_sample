# Cloud Run メモ

## 概要

フルマネージド・サーバーレスプラットフォームです。

コンテナイメージ（Dockerイメージ）を用意するだけで、インフラの構築・管理・運用管理を行わずにアプリケーションを実行できる。

### 詳細

1. インフラ管理が不要
    - サーバの構築・運用はGCPで行う。

2. 高速な自動スケーリング
    - アクセスに応じてインスタ数が自動でスケーリングする。
    - リクエストがない時間帯はインスタンスを「0」にするので、無駄なアイドル費用が発生しない。

3. プログラム言語・ライブラリの制約がない
    - Dockerイメージが作成できれば考慮不要。

4. 従量課金制
    - リクエストに応じて課金される。

5. ポータビリティ（可搬性、移植性）
    - 「Knative」ベースで構築しているので、Kubernetesを利用した他社への移植もしやすい。

6. 2種類のコンポーネント
    - Cloud Run Services：Webシステム向け
    - Cloud Run Jobs：バッチなどの定期タスク

## 公開方法

### 手順
1. ソースコードをビルドしてDockerイメージを作成する。
2. Dokcerイメージを**Artifact Registry**にPushする。
3. Artifact Registoryはデプロイして利用可能となる。
    - `gcloud run deploy`コマンドを実行すると、自動でHTTPS対応のURLが発行されて即時に公開される。

## 疑問点と回答

- マシンスペックを選ぶことは可能か？
    - 「CPU数」と「メモリ容量」を選択することが可能

- ステートフルを実現する方法
    - ① データ・ストレージのステートフル化
        - 1-1. Cloud Storage（GCS）バケットのマウント
            - Cloud Storageをコンテナ内のローカルディレクトリとしてマウントする
                - 動画等のファイルサイズが大きものは有効
        - 1-2. NetWork File System(NFS)/Filestoreのマウント
            - 共有のファイルサーバー（Filestore等）をマウントする
        - 1-3. 外部データベース（Cloud SQL/Valkey/Spanner）への状態外部化
            - データベースやインメモリキャッシュにステートを保存する
    - ② 通信・セッションのステートフル化（Sticky Sessions）
        - 2-1. セッションアフィニティ（Session Affinity）の有効化
            - Cookieを利用して、同一のコンテナインスタンスルーティングをする
        - 2-2. WebSocketやgRPCストリーミングの利用
            - クライアントとコンテナ間で長時間のステートフルな双方向通信こねくしょんを維持する
    - ③ インスタンスの生存維持（ステート破棄の防止）
        - 最小インスタンス数（`min-instances`）の設定：`min-instances = 1`以上に設定することで、コンテナが破棄されず、同一のインスタンスを起動し続ける

- セキュリティ面の強化（ホワイトリスト、ブラックリストの作成）
    - Cloud RunではIPアドレスが変更されることがあるため単純なIPアドレスの制御は一般的ではなく、以下の手法で制御する。
        - ① IAM（Idenitity and Access Management）による認証制御
            - 認証情報（サービスアカウント）を使って通信制御を行う。
                - 1-1. 「呼び出し先」のアクセス制御で「未承認の呼び出しを許可しない」設定を行う
                - 1-2. 「呼び出し元」に紐づけたサービスアカウントに対して、「呼び出し先」を呼び出す権限を付与する
                - 1-3. 「呼び出し元」が呼び出す際にリクエストの`Authorization`ヘッダーに`Google OCIDC ID`トークンを付与する
        - ② Ingress（受信制御）の設定
            - 「呼び出し先」へのアクセス経路をネットワークレベルで制限する方法。
                - Cloud Runの設定で外部インターネットからの直接アクセスを遮断して、内部トラフィックのみ受け付けるように制限する
