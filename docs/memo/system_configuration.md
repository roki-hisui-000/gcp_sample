# システム構成定義書 (System Configuration)

本システムは、セキュリティ、スケーラビリティ、およびデプロイの柔軟性を高めるため、フロントエンド（Gateway機能内包）とバックエンド（API・DBアクセス担当）を完全に分離した **「2コンテナ ＋ 1インメモリDB」** の3層構造で構築されています。

---

## 1. 全体アーキテクチャ図

```
[クライアント (ブラウザ)]
       │
       │ ① 画面取得 / ② APIリクエスト (Cookie同梱)
       │ (同一オリジン: http://localhost:8080)
       ▼
┌────────────────────────────────────────────────────────┐
│ 1. Frontend コンテナ (Gateway)                          │
│   - React (Viteビルド成果物) の静的配信                 │
│   - /api/* へのリクエストを backend へ転送 (プロキシ)   │
└──────────────────────────┬─────────────────────────────┘
                           │
                           │ ③ プロキシ転送 (内部ネットワーク)
                           ▼
┌────────────────────────────────────────────────────────┐
│ 2. Backend コンテナ (API)                              │
│   - ビジネスロジック処理（メッセージ加工、時刻付与等）   │
│   - セッション管理（express-session + connect-redis）  │
└──────────────────────────┬─────────────────────────────┘
                           │
                           │ ④ セッションの読み書き
                           ▼
┌────────────────────────────────────────────────────────┐
│ 3. Valkey コンテナ (インメモリDB)                      │
│   - セッションデータの永続化（名前・セッションIDの維持） │
└────────────────────────────────────────────────────────┘
```

---

## 2. 各コンテナの役割と技術スタック

### ① Frontend コンテナ (`frontend`)
*   **ポート**: `8080` (ブラウザから直接アクセスする唯一の窓口)
*   **技術スタック**: Node.js (V20-alpine) / Express / `express-http-proxy`
*   **フロントエンド画面**: React 18 / Vite 5
*   **詳細な役割**:
    *   ブラウザから画面要求があった際、ViteによってビルドされたReactの静的ファイル（HTML/CSS/JS）を配信。
    *   ブラウザから `/api/*` への通信があった場合、Cookie（セッションID）を保持したまま `backend` コンテナに中継（プロキシ）する。これによりCORS（オリジン制限）を完全に回避。

### ② Backend コンテナ (`backend`)
*   **ポート**: `8080` (内部通信用、ローカル検証用ホスト公開は `8081`)
*   **技術スタック**: Node.js (V20-alpine) / Express / `express-session` / `connect-redis` / `ioredis`
*   **詳細な役割**:
    *   ログイン（名前登録）、ログイン状態の確認、チャットメッセージの処理などのビジネスロジックを担当。
    *   セッションストアとして Valkey を使用し、ユーザー情報の安全な書き込み・読み込みを行う。

### ③ Valkey コンテナ (`valkey`)
*   **ポート**: `6379`
*   **技術スタック**: Valkey 8.0 (Dockerイメージ: `valkey/valkey:8`)
*   **詳細な役割**:
    *   セッションキーをメモリ上に安全に保持。セッションIDをキーに、ユーザー名などの状態を永続化する。

---

## 3. セッション管理とCookie維持の仕組み

1.  **名前の登録**: ブラウザから送信された `username` を、`backend` が Valkey に保存し、一意の `セッションID (connect.sid)` を生成。
2.  **Cookieの返却**: 生成されたセッションIDは、レスポンスの `set-cookie` ヘッダーを通じてブラウザに送り返され、ブラウザがこれを保存。
3.  **プロキシによるドメイン統一**: ブラウザは常に同一のオリジン（`localhost:8080`）と通信していると認識するため、異なるポートにまたがるCORS制限に引っかかることなく、安全にCookieが自動送信・維持されます。

---

## 4. 環境ごとの構成差異

### ローカル開発環境 (`docker-compose`)
*   **Frontend**: `BACKEND_URL=http://backend:8080` で内部ネットワーク接続。
*   **Backend**: `VALKEY_HOST=valkey` でローカルValkeyコンテナに接続。

### 本番環境 (Google Cloud)
*   **Frontend**: Cloud Run (`gcp-sample-frontend`) として起動。`BACKEND_URL` に `gcp-sample-backend` のサービスURLを設定。
*   **Backend**: Cloud Run (`gcp-sample-backend`) として起動。Serverless VPC Access経由で Memorystore for Valkey に接続。
*   **Valkey**: GCP Memorystore for Valkey (`my-valkey`) を使用。`VALKEY_HOST` には必ず **PRIMARY（読み書き可能）ノードのIPアドレス** を指定（READERノードを指定するとセッションの書き込み時に500エラーになるため注意）。
