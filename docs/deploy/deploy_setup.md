# 環境構築

GCP（Google Cloud Platform）の **Cloud Run** を使って、本システムをインターネット上に公開するための「GCP側の構築・準備手順」を解説します。

現在 **Plan（計画）モード** ですので、まずはGCPのコンソール画面（Webブラウザ）やコマンドラインで行う準備作業のステップを詳細に説明します。

---

## ☁️ GCP側構築ステップ（Cloud Run デプロイ準備）

Cloud Run へのデプロイには、大きく分けて以下の **5つのステップ** が必要です。

1. **Google Cloud プロジェクトの作成**
2. **課金（Billing）の有効化**（※無料枠内で動かすためにも必要です）
3. **必要な Google API の有効化**
4. **Artifact Registry（コンテナイメージ保管庫）の作成**
5. **ローカル環境の認証（gcloud CLI の初期化）**

それぞれの具体的な手順を解説します。

---

### Step 1. Google Cloud プロジェクトの作成
GCPでは、すべてのリソース（Cloud Run、データベースなど）を「プロジェクト」という単位で管理します。

1. [Google Cloud コンソール](https://console.cloud.google.com/)にアクセスしてログインします。
2. 画面上部のプロジェクト選択メニューをクリックし、**「新しいプロジェクト」** を選択します。
3. 任意のプロジェクト名を入力します。
   * 例: `gcp-sample-project`
4. **「作成」** をクリックします。作成完了後、そのプロジェクトに切り替えます。
5. 作成された **「プロジェクトID」**（例: `gcp-sample-project-452108` のような自動付与された識別子）を控えておきます。このIDはコマンド等で頻繁に利用します。

---

### Step 2. 課金（Billing）の有効化
Cloud Run を利用するには、プロジェクトに請求先アカウントを紐付ける必要があります。
* **💡 安心ポイント**: Cloud Run には非常に緩い**永久無料枠**（毎月200万リクエストまで、CPU/メモリ使用量にも一定の無料枠あり）があるため、個人での検証目的であれば請求が発生することはほぼありません。

1. Google Cloud コンソールの左メニューから **「お支払い (Billing)」** を選択します。
2. 画面の指示に従い、クレジットカード等の支払い情報を登録した請求先アカウントをプロジェクトに紐付けます。

---

### Step 3. 必要な API の有効化
Cloud Run のデプロイやイメージの作成には、GCPのいくつかの機能を有効化する必要があります。

Webコンソールで有効化することもできますが、ローカルのターミナル（`gcloud` コマンド）から一括で有効化するのが最も簡単です。

**有効化する主要API:**
1. **Cloud Run API** (`run.googleapis.com`): Cloud Runの実行に必要。
2. **Artifact Registry API** (`artifactregistry.googleapis.com`): Dockerイメージを安全に保存・管理する場所に必要。
3. **Cloud Build API** (`cloudbuild.googleapis.com`): GCP上でDockerイメージを自動ビルドするために必要。

※ 実際の有効化コマンドは、Step 5 で `gcloud` の認証が終わった後に実行します。

---

### Step 4. Artifact Registry（リポジトリ）の作成
Cloud Run にコンテナをデプロイするには、ビルドした Docker イメージを GCP 上のリポジトリ（**Artifact Registry**）にアップロードしておく必要があります。

1. コンソールの検索窓で「**Artifact Registry**」を検索し、移動します。
2. **「リポジトリの作成」** をクリックします。
3. 以下の設定値で入力・選択します：
   * **名前**: `gcp-sample-repo` (任意)
   * **形式**: `Docker`
   * **モード**: `標準`
   * **ロケーションタイプ**: `リージョン`
   * **リージョン**: `asia-northeast1 (東京)`（日本のユーザー向けに低レイテンシで最もおすすめのリージョンです）
4. **「作成」** をクリックします。

---

### Step 5. ローカルPCでの認証と初期設定
GCP側の準備ができたら、ローカルPCからプロジェクトを操作できるように Google Cloud SDK (`gcloud` CLI) のセットアップと認証を行います。

まだ `gcloud` がインストールされていない場合は、Google公式ドキュメント等に従ってインストールを行ってください。

1. **gcloud CLIへのログイン**
   ターミナルを開き、以下のコマンドを実行します。ブラウザが立ち上がるので、GCPに登録したGoogleアカウントでログイン・認証します。
   ```bash
   gcloud auth login
   ```
2. **プロジェクトの設定**
   先ほど作成した「プロジェクトID」を、デフォルトの操作対象として登録します。
   ```bash
   gcloud config set project [あなたのプロジェクトID]
   ```
3. **必要なAPIの一括有効化（コマンドで実行）**
   Step 3 で説明したAPIを一瞬で有効化します。
   ```bash
   gcloud services enable run.googleapis.com \
                          artifactregistry.googleapis.com \
                          cloudbuild.googleapis.com
   ```

## 📅 デプロイ構築スケジュール案

現在の進捗としては、ローカルでの動作確認が完了しているため、次にやるべきことは以下のステップになります。

1. **`gcloud` CLI の設定状況確認**
   * ローカルPCにすでに `gcloud` が入っているか、GCPアカウントがあるかを確認します。
2. **`docker-compose.yml` の不要な警告（WARN）の修正**
   * 先ほど説明した `version` の行を消して綺麗にします。
3. **デプロイ手順のドキュメント化（README.md の更新）**
   * この後のデプロイ実行時に迷わないよう、`README.md` に具体的なコマンドなどをまとめます。
4. **デプロイの実行**
   * 実際に Cloud Run へデプロイし、公開URLで動くことを確認します。

まずは、**お使いのローカルPCにすでに `gcloud` コマンドがインストールされているかどうか**を教えていただけますでしょうか？
また、この段階で「Act（実行）モード」に切り替えて、警告の修正やドキュメントの記載、そしてデプロイ作業を開始しても良いかご指示ください！
